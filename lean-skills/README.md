# lean-skills — рабочий минимум вместо большого пакета скилов

Четыре скила взамен пакета из четырнадцати. Ставятся как **личные скилы**: без плагина, без
маркетплейса и **без единого хука**.

## Зачем это существует

Большой пакет скилов платит за себя контекстом **в каждой сессии**, а окупается в той, где
пригодился. Замер по реальной истории работы — 1288 журналов сессий, 36 проектов, поиск фактических
вызовов инструмента скилов:

| Скил большого пакета | Вызовов за всю историю |
|---|---|
| systematic-debugging | 5 |
| writing-plans | 4 |
| brainstorming | 4 |
| subagent-driven-development | 2 |
| dispatching-parallel-agents · test-driven-development · writing-skills | по 1 |
| **verification-before-completion** | **0** |
| requesting-code-review · receiving-code-review | 0 |
| finishing-a-development-branch · executing-plans · using-git-worktrees | 0 |

**19 вызовов за всю историю.** При этом мета-скил пакета впрыскивался в контекст **при каждом
старте сессии, каждой очистке и каждом сжатии контекста** — 3.3 КБ текста, содержание которого
сводится к требованию вызывать скилы:

> «If you think there is even a 1 % chance a skill might apply to what you are doing, you
> ABSOLUTELY MUST invoke the skill… This is not negotiable. You cannot rationalize your way out of
> this.»

Плюс ~2 КБ описаний четырнадцати скилов, висящих в системном промпте постоянно.

### Что изменилось в цифрах

| | Большой пакет | lean-skills |
|---|---|---|
| Скилов | 14 | 4 |
| Тела скилов на диске | 448 КБ | **9.8 КБ** |
| Постоянно в контексте (описания) | ~2 КБ | **0.7 КБ** |
| Впрыск на старт / очистку / сжатие | 3.3 КБ | **нет** |
| Хуков | 1 (`SessionStart`) | **0** |

Постоянный расход контекста снижен примерно с 5.3 КБ до 0.7 КБ. Это **не ноль**: описания
скилов движок показывает всегда — иначе он не сможет их предложить.

## Принцип отбора

Оставлено то, что удовлетворяет **всем** условиям:

1. **есть ядро** — конкретный приём, которого модель не делает по умолчанию;
2. **не требует того, чего нет** — git-flow с remote и CI, обязательного git-репозитория,
   bash-скриптов, GitHub API;
3. **не принуждает** — правила формулируются как правила, а не как «это не обсуждается».

Что выброшено и почему:

| Выброшено | Причина |
|---|---|
| мета-скил «обязан вызывать скилы» | ядра нет, а платит контекстом каждую сессию — **главная статья расхода** |
| «исполнение плана» | дублирует поведение по умолчанию |
| «параллельные подагенты» | ядро — один факт (несколько вызовов в **одном** ответе идут параллельно); он перенесён в `delegating-to-subagents` |
| «написание планов» | из содержательного — два пункта (сверять имена по всем задачам; соразмерять церемонию), они перенесены туда же: аудитория одна — исполнитель, не видящий разговора |
| «тест раньше кода» | классический цикл модель воспроизводит и без подсказки; неочевидное («назвать заранее, какое изменение уронит тест», требования к скрипту-гейту) перенесено в `verifying-before-claiming` |
| «worktree», «завершение ветки», «запрос ревью» | целиком про git-flow с remote, PR и CI |
| «brainstorming» | жёсткий гейт «не писать код до утверждения дизайна» спорит с правилом соразмерять церемонию задаче |
| вспомогательные файлы (локальный Node-сервер, тестовые артефакты автора, 46 КБ best-practices) | ~570 КБ, для работы не нужны |

⚠️ Отдельно: в исходном пакете лежал файл с **приёмами давления на модель** (авторитет, дефицит,
социальное доказательство) как инструкция автору скилов. Здесь такого нет намеренно: скил, который
работает только под нажимом формулировок, не работает.

## Установка

Скопировать содержимое `skills/` в личный каталог скилов:

```
<user-home>\.claude\skills\<имя-скила>\SKILL.md
```

Больше ничего не требуется: ни списка включённых плагинов, ни маркетплейса, ни регистрации хуков.
**Выключить большой пакет**, если он стоял, — убрать его из `enabledPlugins` в
`<user-home>\.claude\settings.json`.

⚠️ **Проверьте, не занят ли триггер.** Если у вас уже есть свой скил про написание скилов или про
разбор ошибок, два скила будут ловить одну ситуацию, и агент возьмёт любой. Развести описания или
оставить один.

## Известное ограничение

`verifying-before-claiming` срабатывает **реже, чем следовало бы**: его момент — тот, когда агент
уже завершает работу и за скилами не ходит. Именно поэтому в исходном пакете его аналог не был
вызван **ни разу**. Описание здесь расширено более ранними признаками (зелёный прогон, приёмка
чужого отчёта, подготовка коммита), но надёжно это решается только внешним напоминанием — например
хуком на завершение хода. Хук здесь сознательно не ставится: он вернул бы ровно то свойство, ради
избавления от которого пакет и урезан.

## Как написаны описания

`description` каждого скила содержит **только триггеры** — когда его брать — и никогда не пересказ
содержимого: если в описании пересказан порядок действий, агент выполняет **описание** вместо того,
чтобы открыть скил. Ключи продублированы по-английски, потому что рабочие сессии смешивают языки, а
совпадение ищется с тем, что у агента на руках.
