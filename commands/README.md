# Working commands (Claude Code slash-commands)

Переиспользуемые **slash-команды** Claude Code, наработанные в практике
agent-backed workspace. Каждый `.md` здесь — готовый промпт-шаблон: кладёшь
файл в каталог команд Claude Code, и он вызывается как `/<имя-файла>`.

## Установка

Скопировать нужный `.md` в каталог команд Claude Code:

- **Глобально (для всех проектов):** `~/.claude/commands/<name>.md`
- **Только для одного репозитория:** `<repo>/.claude/commands/<name>.md`

После этого команда доступна как `/<name>` в сессии. Содержимое `.md` —
это инструкция, которую Claude получает при вызове команды (не код).

## Команды

| Команда | Назначение |
|---------|------------|
| [`handoff-myself.md`](handoff-myself.md) | **Сверка долговременной памяти роли** перед `/compact` или закрытием сессии: пройти по семи признакам (что было бы катастрофой потерять, что оказалось неожиданным, что дорого выяснить заново, непереигрываемые решения с причиной, отвергнутые варианты, незакрытые задачи, рабочая рутина) и привести записи в соответствие с тем, что известно сейчас. Память — каталог записей на роль, одна запись = один предмет. |

### Почему handoff-myself полезна

Координация агента **с самим собой через время** — через сжатие контекста и
перезапуск сессии.

⚠️ **Команда сменила предмет.** Ранняя версия писала один растущий
handoff-файл; сейчас она ведёт **каталог записей** — по файлу на предмет плюс
индекс, который движок вклеивает в контекст сам. Причина смены: один файл
решает хранение и не решает извлечение, а замеры показали, что он растёт
быстрее, чем его успевают чистить (+70 % за двое суток у активной роли; 11 из
68 файлов перестали помещаться в одно чтение). Устройство памяти, замеры и
отвергнутые варианты — [Agent Long-Term
Memory](../docs/agent-long-term-memory.md).

Ключевое в команде — не «дописать, что вспомнилось», а **сверка**: по каждому
факту ответить, записан ли он, не устарело ли записанное, не противоречит ли
новое старому. Пустой проход законен. Отдельно оговорены правила, без которых
уборка **теряет** содержание: править только то, с чем работал в этой сессии;
не переписывать файл целиком; не трогать дословные формулировки решений,
запретов и замеров.
