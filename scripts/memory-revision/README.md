# scripts/memory-revision/ — модуль актуализации памяти

Рабочий код механики, описанной в [`docs/memory-actualization.md`](../../docs/memory-actualization.md):
машинный список записей на перепроверку, помощник-вердиктчик, закрытие исходов пачкой, подсадные
позиции. Обезличенные копии боевых файлов.

🛑 **Это надстройка над памятью, а не её часть.** Она стоит одного отдельного агента на каждую
свёртку и заметно дорожает свёртку. Ставить, когда у роли **сотня и больше** записей и она уже
поймала себя на том, что действует по устаревшей. До этого достаточно
[`../agent-memory.ps1`](../agent-memory.ps1) и [`commands/handoff-myself`](../../commands/handoff-myself.md)
без модуля — команда это умеет (ответ `HANDOFF-REFUSED`). Сначала — вводный блок корневого README.

## Из чего состоит и кто кого зовёт

| Файл | Что делает | Кто зовёт |
|---|---|---|
| `memory-revision.py` | **Сборщик списка актуализации**: записи, давно не подтверждавшиеся (по `checked:`, без него — по git), пункты по письмам шины, противоречия внутри записи; порция на проход; атомарная запись; отметка окна по началу прохода; журнал исходов прошлого списка (`harvest`). Список кладёт в `.revision/<роль>.md` **вне** каталога памяти. | [`../memory-audit.ps1`](../memory-audit.ps1) — из хука `PreCompact` и из `pool handoff` ([`../pool.ps1`](../pool.ps1)) |
| `memory-verdicts.py` | **Помощник-вердиктчик**: по каждому пункту зовёт `claude -p --agent memory-verdict`, кладёт вердикты в `.revision/verdicts-<роль>.{md,json}`; общий замок на машину, число потоков — по свободной памяти; `--wait` для роли; штамп окна. Переменные идентичности роли из окружения помощника **вычищаются** — иначе хуки принимают его за роль. | `memory-revision.py` фоном; роль — только `--wait` |
| `memory-close.py` | **Закрыватель**: один файл исходов → один запуск; вписывает исходы в список, ставит `checked:`, называет пункты без исхода, «подтверждено» без основания, исходы не из словаря, список, пересобранный после файла исходов. 🛑 Четвёртое поле — дословная цитата из записи, сверяется с цитатами помощника. Читает и пишет байт-в-байт. | роль — по строке `ЗАКРЫВАТЕЛЬ:` из вывода `pool handoff` (`memory-audit.ps1`) и строке «исходы закрывать ПАЧКОЙ» в `memory-check.ps1` |
| `plant.py` | **Подсадные**: одна позиция на проход из реестра отменённых утверждений; подложный вердикт кладётся в тот же `.md`, что и настоящие; `--check` сверяет исход роли с истиной и пишет `caught` / `missed` / `lost` в `planted-done-<роль>.jsonl`. | `memory-verdicts.py` после расчёта; `--check` — обвязка на следующем проходе |
| `mark_checked.py` | Единственная реализация метки `checked:` в шапке записи. | `memory-close.py` |
| `verdict-stats.py`, `journal-dedup.py` | Сводка по вердиктам; дедуп журнала после сбоя. | руками |
| `probe-*.py` | Пробы: сборщик, помощник (с заглушкой движка `probe-stub-engine.py`), закрыватель (15 проверок на списке, собранном настоящим сборщиком), штамп помощника. Три мутации закрывателя обязаны краснеть. | руками, перед выпуском |
| `agents/memory-verdict.md` | Определение агента-помощника для `claude -p --agent memory-verdict`: только чтение, формат вердикта с цитатами. | движок |

## Установка

1. Память ролей уже включена ([`../agent-memory.ps1`](../agent-memory.ps1), `docs/agent-long-term-memory.md` §6).
2. Каталог модуля — рядом со скриптами: [`../memory-audit.ps1`](../memory-audit.ps1) и
   [`../memory-check.ps1`](../memory-check.ps1) ищут его первым кандидатом в `memory-revision\`
   относительно себя (в источнике он лежал иначе — `shop/` на сервере, `server/memory-revision/`
   на рабочей машине; оба кандидата оставлены).
3. `python3` в `PATH` (на Windows проверяется ответом на `--version`: заглушка из WindowsApps не
   считается), `claude` CLI, и агент: скопировать `agents/memory-verdict.md` в `~/.claude/agents/`.
4. Реестр отменённых утверждений в памяти роли (`reference_revoked-claims.md` или аналог) — без него
   подсадным неоткуда браться, модуль работает без них.

## Приёмка

`python3 probe-memory-close.py` → 15/15 и три мутации красные; `probe-memory-revision.py`,
`probe-memory-verdicts.py` (движок — заглушка, сеть не нужна), `probe-verdicts-stamp.py` — зелёные. Живой прогон: `pool handoff -Owner <роль>` печатает строки
`СПИСОК:`, `ВЕРДИКТЫ ЖДАТЬ:`, `ЗАКРЫВАТЕЛЬ:`; через 1–2 минуты команда ожидания печатает вердикты.

Что из этого мерится и чего измерить пока нельзя — `docs/memory-actualization.md` §7–8, §10.
