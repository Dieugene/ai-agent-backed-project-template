# scripts/obligations/ — слой осознанных коммуникаций: обходчик, антифлуд, замеры, пробы

Рабочий код механики, описанной в [`docs/agent-messaging/`](../../docs/agent-messaging/README.md).
Обезличенные копии боевых файлов: имена пулов заменены на `pool-A`, `pool-B-N`, `pool-stand`,
пути — на `<workspace-root>`, `<probes-dir>`, `<user-home>`.

🛑 **Сначала — вводный блок корневого README.** Эта механика заводилась против конкретной боли —
длинных рассуждений о малозначимом в пулах сопровождения — и стоит обслуживания: таймер раз в
минуту, письма ролям, замеры. Если у пользователя один пул из двух ролей и переписка не
разрастается, ставить её не нужно; читайте документы, а код не трогайте.

## Из чего состоит и кто кого зовёт

Форма писем (поля `Opens` / `Expect` / `CloseWhen` / `About` / `Closes` / `Outcome`), события
`close` / `amend` и свод открытых обязательств в `pool mine` живут **не здесь**, а в ядре шины —
[`../pool.ps1`](../pool.ps1). Здесь — то, что работает поверх писем.

| Файл | Что делает | Кто зовёт |
|---|---|---|
| `shop-flood.py` | **Антифлуд** — таймер раз в минуту по всем пулам (по `pool.manifest.json`): счёт писем за час по пулу и по паре ролей, напоминание ведущему при пороге (`всего ≥ 25` или `пара ≥ 12`), исходящих одной роли ≥ 12 — напоминание роли. Пороги подобраны прогоном по архиву, обоснование в шапке файла. | системный таймер (у нас — юнит systemd вне репозитория). **Только Linux/macOS**: замок через `fcntl`, на Windows не импортируется |
| `shop_oblig.py` | **Обходчик обязательств**: сбор открытых/закрытых из шапок писем, накопительный индекс по пулу, сводка между пулами (`cross.json`), письма авторам о нарушениях формы (четыре предохранителя: засев, отпечатки, потолок попыток, отказ вместо «чистого листа»). | `shop-flood.py` после каждого прохода — **не** сам по себе: ветка `--all` руками, и это ловушка, описанная в `docs/agent-messaging/07-operations.md` |
| `rollout_gate.py` | Сторож замера итогов: считает ролевые письма после границы внедрения и напоминает, когда порог набран. | `shop-flood.py` |
| `measure_oblig.py` | Замер переписки до/после границы: доля писем с полями, кто закрыл, события реестра, длины формулировок, диагностика. `--bus <шина> --split <мс>` | руками |
| `measure_tempo.py` | Темп: ролевых писем в сутки до/после. `<шина> <split_ms>` | руками |
| `chain_decay.py` | Затухают ли обмены: цепочки под ключом обязательства или тредом, длина, «нарастает ли» по дням. `<шина> <split_ms> [<шина>…]` | руками |
| `oblig_breakdown.py` | Раскладка обязательств по содержанию (дела людей / картотека / устройство инструментов) — для разбора ведущим. | руками |
| `measure-base-before.py`, `measure-poklony.py` | База «до»: сколько ожиданий открывалось и закрывалось прозой; замер «поклонов» (их не оказалось: 1 на 3 013 отправок). | руками, один раз |
| `dump_field_notes.py` | Реестр обязательств одной шины полями как есть — исходные данные для разбора. | руками |
| `probes/` | Пробы и мутации: `probe_close.py` (25), `probe_cross.py` (18), `probe_notify.py` (15), `probe_expect.py`; `mutate_close.py` (10), `mutate_expect.py`. Все мутации обязаны краснеть — иначе проба пустая. | руками, перед выпуском |

## Установка — по частям

1. Ядро шины: [`../pool.ps1`](../pool.ps1) уже несёт форму и события; отдельно ставить нечего.
   Правила для ролей — [`docs/agent-messaging/COORDINATION.md`](../../docs/agent-messaging/COORDINATION.md)
   (они печатаются ролям скилом; без доставки правил механика мертва — `06-feedback.md`).
2. Антифлуд: `shop-flood.py` под таймером раз в минуту с корнем, под которым лежат пулы. Он
   находит пулы по `pool.manifest.json`; пул без манифеста для него не существует.
3. Обходчик: ничего не запускать отдельно — его зовёт антифлуд. Сухой прогон:
   `python3 shop_oblig.py --all --notify-dry`.
4. Пробы требуют `pwsh` (PowerShell 7); пути к `pool.ps1` и `shop_oblig.py` они берут относительно себя
   (`../../pool.ps1`, `../shop_oblig.py`) — переносить каталог целиком.
5. `rollout_gate.py` привязан к конкретному внедрению: без переменных `ROLLOUT_GATE_BUS`, `ROLLOUT_GATE_TO`,
   `ROLLOUT_GATE_NOTIFY_BUS`, `ROLLOUT_GATE_SINCE_MS` он громко отказывает; не нужен — уберите вызов из `shop-flood.py`.

## Приёмка

`python3 probes/probe_close.py` → 25/25; `probe_cross.py` → 18/18; `probe_notify.py` → 15/15;
`python3 probes/mutate_close.py` → все 10 мутаций пойманы **своей** проверкой. Два мутационных
прогона на одном файле параллельно не пускать — мутация одного становится «дефектом» другого.

Замеры, которыми проверялась механика на живой переписке, и их результаты —
[`docs/agent-messaging/08-measurements.md`](../../docs/agent-messaging/08-measurements.md).
