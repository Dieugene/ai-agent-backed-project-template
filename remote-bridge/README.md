# remote-bridge — удалённый пульт к своей Claude-сессии через Telegram

Управляй **своей же** живой сессией Claude Code (или пулом агентов) из Telegram — с телефона,
из любого места. Пишешь боту в личку → сообщение долетает до активной сессии-цели; сессия
делает работу и отвечает обратно в тот же чат. Голос (STT) и текст. Работает **за NAT**
(Telegram long-polling — входящих портов открывать не надо).

> **ОДНА копия кода** на весь workspace (как общий CLI). Разные сессии/проекты подключаются
> **конфигом + окружением**, код не копируется. Пишет только доверенный владелец (гард по
> числовому Telegram `user_id`).

## Что это даёт

- **Пуш-канал в сессию:** входящее ЛС будит нужную сессию-цель, не тратя её контекст на опрос.
- **Ответ из сессии:** единственный исходящий канал (`send_message.py`) с allowlist-ом чатов и журналом.
- **Пул или solo:** для пула — переключение цели `/switch` инлайн-кнопками (роли из манифеста);
  для одиночной сессии — одна фиксированная цель.
- **Голос:** слот STT (`none` / `openai` / `faster_whisper`).
- **Живучесть:** авто-перезапуск, автозапуск при логине, Stop-хук держит сторож взведённым.

## Состав

| Файл | Назначение |
|---|---|
| `bridge.py` | фоновый процесс: long-polling → журнал → побудка; гард по `user_id` + TOFU; `/switch` + callback; media |
| `bridgelib.py` | общий код: резолвинг инстанса, Bot API (санитизация токена), журнал, конфиг, state владельца/цели |
| `tools/send_message.py` | единственный исходящий канал сессии (allowlist чатов, журнал outbox) |
| `tools/read_inbox.py` | выдача новых сообщений владельца, сдвиг курсора |
| `tools/chat_sentinel.py` | быстрый (~2 с) сторож журнала, целе-зависимый; будит сессию-цель |
| `tools/remote_sentinel_gate.ps1` | Stop-хук: держит сессию-цель, если сторож не взведён при живом мосте |
| `stt/provider.py` | слот STT (ключ — в `secrets/.env`) |
| `run-bridge.ps1` | общий runner (авто-перезапуск; exit 2 = fatal) |
| `autostart.ps1` + `autostart.example.json` | автозапуск инстансов при логине (папка «Автозагрузка») |
| `config.example.{pool,solo}.json` | шаблоны конфига |
| `tests/test_bridge.py` | оффлайн self-test (без сети и токена) |

## ⚠️ Перед запуском — впиши свой путь

Код хардкодит абсолютный путь к самому себе (в hint-строках сторожа/гейта и к пулу `pool.ps1`).
Публикуется он с плейсхолдером **`<workspace-root>`**. Сделай глобальный find/replace во всём разделе:

```
<workspace-root>   →   <абсолютный путь твоего workspace>   (напр. D:\work  или  /home/you/work)
```

Раздел ждёт раскладку `<workspace-root>/.launcher/pool-bus/remote-bridge/…`. Если у тебя иначе — поправь
пути в `bridgelib.py` (`POOL_PS1`), `bridge.py`, `tools/chat_sentinel.py`, `tools/remote_sentinel_gate.ps1`.

## Быстрый старт — подключи своего бота

1. **Создай бота** у [@BotFather](https://t.me/BotFather) → получи токен. Для режима **pool** отключи
   Privacy Mode (`/setprivacy` → *Disable*).
2. **Заведи инстанс** — папку `<project>/secrets/` (вне git!):
   - `bot.token` — токен от BotFather, одна строка (формат `^\d+:[A-Za-z0-9_-]{20,}$`);
   - `bridge-config.json` — по схеме ниже (можно оставить `allowed_user_id: 0` → тебя зафиксирует
     первое ЛС, TOFU);
   - *(опц.)* `.env` с `OPENAI_API_KEY=…` — только при `stt.provider = openai`.
3. **Запусти мост:**
   ```
   powershell -File run-bridge.ps1 -ProjectDir <project>
   ```
   Мост уходит в long-poll. Нет токена → просто ждёт (лог 1 раз + backoff), не падает.
   Здоровье — `<project>/03_data/state/bridge-health.json`.
4. **Первое ЛС боту** при пустом `allowed_user_id` фиксирует твой `user_id` (TOFU) в
   `state/owner.json` и подтверждается в чат. Дальше гард пускает только тебя.

Рантайм (журнал/state/media/логи) — `<project>/03_data/` (pool) либо `data_dir` из конфига (solo).
Резолвинг инстанса: `--project-dir` **>** `REMOTE_BRIDGE_PROJECT_DIR` **>** `POOL_BUS_ROOT` (родитель `.bus`).

## Как сессия общается с ботом (цикл)

Мост — это демон на стороне бота. Твоя **сессия-цель** (агент Claude Code) держит канал так:

1. **Взводит сторож** — фоновой задачей: `python tools/chat_sentinel.py`
   (переживает `/compact`, но НЕ рестарт сессии — тогда перевзвести).
2. **На каждое входящее** (сторож будит сессию, выходя из фоновой задачи):
   `read_inbox.py` → сделать работу → `send_message.py --chat <owner_id> --text-file <utf8-файл>`
   → **снова взвести сторож**.
3. **Stop-хук** `remote_sentinel_gate.ps1` детерминированно держит сторож взведённым, пока мост жив.

## Схема `bridge-config.json`

| Ключ | Дефолт | Смысл |
|---|---|---|
| `mode` | `"pool"` | `pool` (цели из манифеста, `/switch` кнопками, резервный `.bus`-wake) или `solo` (одна фикс. цель) |
| `allowed_user_id` | `0` | числовой TG `user_id` владельца; `0`/нет → TOFU по первому ЛС |
| `allowed_chats` | `[]` | доп. `chat_id` для `send_message` (личка владельца разрешена всегда) |
| `default_target` | `null` | pool: дефолт текущей цели (иначе `lead` манифеста); **solo: обязательная фикс. цель** |
| `data_dir` | `null` | solo: корень рантайм-данных; `null` → `<project>/03_data` |
| `stt` | `{"provider":"none"}` | `none` / `openai` / `faster_whisper` |
| `wake_debounce_s` | `60` | дебаунс резервного `.bus`-wake (pool) |

Готовые примеры: `config.example.pool.json`, `config.example.solo.json`.

## Модель доверия (важно)

Гард моста — **allowlist-of-one** по числовому `user_id`: до сессии доезжают **только сообщения
владельца** (чужие → в `quarantine-*.jsonl`, без контента и без побудки). Значит содержимое канала —
**распоряжения владельца**, и сессия их исполняет; выдача `read_inbox` НЕ маркируется «недоверенным
вводом».

На уровне КОДА (владельца не ограничивает — просто не даёт мосту стать дырой): движок не `eval`-ит
текст и не подставляет его в shell/пути; имя файла на диске — только из `file_unique_id`; текст
режется по 16 КБ (анти-DoS журнала); токен не печатается (сетевые исключения санитизируются).
Единственное послабление парсинга — закрытый словарь управляющих входов (`/switch` + callback
`to:<owner>`), только от аутентифицированного владельца и по точному совпадению.

## Безопасность / что НЕ в репозитории

**Секретов здесь нет.** Токен бота, `user_id` владельца, данные переписки — всё живёт в
`<project>/secrets/` и `<project>/03_data/`, **вне** этого репозитория (добавь их в `.gitignore`).
Публикуется только движок и примеры-плейсхолдеры. Не коммить свои `secrets/` и `03_data/`.
