# 08 — Замеры: база, два прогона, пороги приёмки

Все числа получены одним инструментом по одной методике. Это важнее самих чисел: разница между
двумя ручными подсчётами неотличима от разницы между этапами.

## Определения, от которых зависит каждое число

| Термин | Как считается |
|---|---|
| письмо | файл в ящике (`new`/`cur`) или в архиве; один идентификатор — одно письмо |
| письмо роли | отправитель не служебный; отправитель берётся **из имени файла**, оно есть всегда |
| поле обязательства | `Opens` / `About` / `Closes` в шапке |
| ключ | значение любого из трёх; в одном письме один ключ считается один раз |
| зонтик | ключ, под которым больше всего писем |
| закрыл ждущий | отправитель закрытия совпадает с отправителем открытия |
| событие | `close` / `amend` — **не письмо**: никому не приходит, ничьего хода не стоит |

⚠️ Поле `Thread` метрикой не годится: в этой шине ответ заводит собственный тред, поэтому «писем
на тред» всегда около единицы и ничего не измеряет. Длину переписки меряем по ключу обязательства.

⚠️ Жизненный цикл обязательства не режется границей этапов: реестр собирается по всей шине один
раз, границей режутся только письма. Иначе обязательство, открытое до границы и закрытое после,
дало бы «не закрыто» в раннем этапе и «закрыл посторонний» в позднем — оба смещения в одну сторону.

## База «до» (пул `pool-A`, 3 013 отправок)

Замер отвечал на вопрос: не насаждаем ли мы поведение, которого нет?

| Что | Доля |
|---|---|
| открытие обязательства выражено прозой | 30% |
| закрытие выражено прозой | 49% |
| хотя бы одно из двух | 63% |
| явное «ответ не нужен» | 4.9% |

⇒ **Жизненный цикл обязательств уже жил в прозе.** Форма не вводит новое поведение, она даёт
имена тому, что и так происходило.

Отдельно мерились «поклоны» (подтверждение без нового содержания, тело ≤ 25 слов): **1 письмо
из 3 013**. Эха (поклон в ответ на поклон) — 0 при 791 определённом родителе. То есть мишенью
были не короткие подтверждения, а длинные письма: 91% длиннее 100 слов.

⚠️ Первая редакция скрипта поклонов дала бы правдоподобное и неверное число: подтверждение
искалось в теме и теле, а содержание только в теле; словарь считал подтверждением «отлично» и «ок»
из технических статусов; веерная рассылка считалась несколькими письмами.

## Два прогона стенда

| Что | Этап 1 (без механики) | Этап 2 (с механикой) |
|---|---|---|
| писем ролей | 78 | 35 |
| из них без полей обязательства | 25 (32%) | 6 (17%) |
| объём | 466 КБ | 86 КБ |
| средний размер письма | 5.5 КБ | 2.4 КБ |
| обязательств открыто / закрыто | 11 / 10 | 5 / 4 |
| **закрыл ждущий / закрыл исполнитель** | **3 / 7** | **4 / 0** |
| писем на обязательство | 4.9 | 5.8 |
| обязательств тяжелее пяти писем | 3 из 11 | 2 из 5 |
| зонтик | 19 писем, 34% объёма | 10 писем, 28% |
| открытий с полем «Требуется» | 0 из 11 | 5 из 5 |
| длина признака (мин/средн/макс) | 55 / 106 / 164 | 183 / 250 / 314 |

**Что взялось:** норма «принимает тот, кто ждал» — полностью. Формулировки перестали быть
пересказом темы.

**Чего замер не может:** отделить влияние механики от влияния режима экономии, действовавшего
на этапе 2 (потолок 2 КБ на письмо). Падение среднего письма вдвое нельзя записать на счёт одной
механики.

**Что не улучшилось:** писем на обязательство стало больше, не меньше. Разбор показал, что это
не флуд, а починка основания, — см. [02-obligations.md](02-obligations.md).

## Пороги приёмки на боевом пуле

Замер «через несколько дней» без условия не делается никогда. Поэтому условие записано числом
и проверяется машиной.

**Когда мерить: 300 ролевых писем после внедрения.** Темп `pool-A` — 88 писем в сутки
(4 239 писем за 48 дней). Стенду хватило 35 писем на содержательное сравнение; 300 — почти
на порядок больше. По времени это около трёх с половиной суток, но условие **не по времени**:
простаивает пул — мерить нечего, и замер честно подождёт.

| Порог | Значение | Откуда взят |
|---|---|---|
| доля ролевых писем с полем обязательства | **≥ 30%**, цель 60% | ровно столько писем (30%) раньше открывали обязательство прозой; каждое из них обязано теперь нести поле. Цель 60% — близко к 63%, доле писем с любым обязательственным смыслом |
| закрытий, поставленных ждущим | **≥ 80%** | правило исключений не имеет, мерить надо близость к сотне. До механики было 30%, с ней и надзором 100%. Восемьдесят = не более одного нарушения из пяти |
| событий `close` | **> 0** | ноль означает, что роли закрывают письмом, и экономия хода не состоялась |

Ниже первого порога — роли не переучились, и дело не в правилах, а в доставке.
Ниже второго — норма не работает, нужен разбор у ведущего.

## Срез после двух недель эксплуатации (14 суток с раскатки)

Тот же скрипт замера, живые шины, служебные отправители исключены. Числа — состояние на день среза, не итог:
перемер по слову владельца назначен «через две обычные недели», и это не он.

| Что | `pool-A` (7 ролей) | `pool-B` (второй по объёму пул) |
|---|---|---|
| писем ролей после раскатки | 748 | 499 |
| из них с полем обязательства | 310 (41 %) | 143 (29 %) |
| событий реестра `close`/`amend` (ходов не стоят) | 78 | 59 |
| обязательств открыто / закрыто | 131 / 126 | 85 / 82 |
| писем на обязательство | 2,9 | 2,3 |
| тяжелее пяти писем | 5 | 2 |
| **закрыл ждущий** (без машинных обязательств) | **76 из 105 = 72 %** | **81 из 82 = 98 %** |
| открытий с `Expect` / с `CloseWhen` | 119 / 131 из 131 | 85 / 76 из 85 |
| длина `Expect`, знаков (средняя) | 106 | 130 |

**Что сошлось.** Приёмку ставит ждущий: 72 % и 98 % против 30 % до механики (у `pool-A` порог 80 % не
взят — там ведущий закрывает то, что открыл ему оператор: привычка одной роли, не дефект механики).
Форма заполняется, а не отбывается: условие закрытия названо у всех открытий `pool-A`, «чего жду» — у 91 %,
формулировки конкретные (сотня знаков, не «жду новостей»). Цепочки короткие: 96 % обязательств закрываются
в пределах пяти писем. Механика разошлась сама: через две недели её используют **девять шин**, раскатывали
на шесть.

**Что не сошлось или нельзя утверждать.** Больше половины писем без полей — в основном ответы внутри
открытых обязательств, у которых инструмент ответа не подставляет привязку: доля занижена изъяном замера.
Темп `pool-A` 86 → 53 письма в сутки, но по дням: 150/72/154/131/96 (ввод картотеки), затем 6, 44/83/39/29/24/33,
потом 3 и 2 — последние двое суток пул почти молчит, а «при той же работе» машина не измеряет; приписать
снижение механике нельзя. Средний размер письма 2,6 → 2,5 КБ: **длина писем — та самая мишень — не
сдвинулась**; замер длины и глубины цепочек ждёт слова владельца.

**Что важно по-крупному.** До механики у переписки не было единицы, которую можно разбирать. Теперь есть:
декларация → ожидаемый исход → фактический исход, с числом писем между. Это и было заложено как предмет
аналитики наравне с трассами рассуждений; кто её ведёт — ведущий пула или кураторы — решение владельца, его
пока нет.
