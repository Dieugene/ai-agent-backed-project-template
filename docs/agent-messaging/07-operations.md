# 07 — Эксплуатация: где запускается, чем проверить, ловушки

## Самая дорогая ловушка внедрения

🛑 **Сбор обязательств в бою идёт НЕ оттуда, откуда следует по коду.** Общий проход
`shop_oblig.py --all` выглядит главным входом — и его не вызывает регулярно никто. Всё крутится
из **антифлуда**: таймер раз в минуту → проход по пулам → сбор по каждому, а после цикла — сводка
между пулами и сторож замера.

Две части механики были написаны в ветке `--all`. Они выглядели сделанными и **не запускались бы
никогда**. Поймано проверкой «а чем это вообще вызывается», а не чтением кода.

**Правило на будущее:** после того как написал фоновую часть, найди процесс, который её реально
позовёт, и убедись, что он её зовёт. «Есть функция» ≠ «работает».

## Карта: что где живёт

| Часть | Где | Что делает |
|---|---|---|
| форма полей | движок шины, сборка шапки | пишет поля обязательств в письмо |
| адрес пула | движок, отдельная функция | в письмо в чужую шину добавляет `FromPool` |
| события | движок, ветки `close`/`amend` | кладёт файл в `archive/`, минуя ящики |
| сбор | модуль обязательств, проход по шине | ведёт `index.json` |
| сводка между пулами | тот же модуль, общий проход | кладёт `cross.json` |
| письма авторам | тот же модуль | шлёт роли замечания |
| свод роли | движок, чтение индекса | печатает при подъёме роли |
| напоминание о правилах | антифлуд, тело письма роли | строка про скил и про тихое закрытие |
| сторож замера | отдельный модуль, зовётся из антифлуда | напомнит, когда пора мерить итоги |

Выключатель рассылки — переменная окружения у антифлуда. Кода для этого трогать не нужно.

## Чем проверить, что живо

```bash
# форма, события, свод, справка
python3 ../../scripts/obligations/probes/probe_close.py          # 25 проверок
# сводка между пулами, включая защиту от тёзок
python3 ../../scripts/obligations/probes/probe_cross.py          # 18
# рассылка замечаний: засев, повторы, сухой прогон
python3 ../../scripts/obligations/probes/probe_notify.py         # 15
# доказательство, что проверки не пустые
python3 ../../scripts/obligations/probes/mutate_close.py         # 10 мутаций
# общий тест движка (эталон 90/91, один пропуск на linux)
pwsh -NoProfile -File ../../scripts/selftest.ps1 | grep self-test
# кому ушло бы письмо о форме, ничего не отправляя
python3 ../../scripts/obligations/shop_oblig.py --all --notify-dry
# накопилось ли достаточно писем для замера итогов
python3 ../../scripts/obligations/rollout_gate.py --check
```

🛑 **Зелёный прогон сам по себе не доказывает ничего.** Он одинаков и когда правило работает,
и когда проверка его не касается. Поэтому рядом с пробами живут мутации: вырезаем по одному
правилу и смотрим, краснеет ли **именно та** проверка, которая его сторожит.

Это ловит пустые проверки. Живой пример: проверка «справка не обрезана» искала маркер, который
встречался в справке **дважды**, и проходила даже на обрезанной справке. Мутация вскрыла —
чинить пришлось проверку, а не код.

## Правка боевого файла под живыми ролями

1. **Патчер с якорями**, а не подмена файла целиком: считаем вхождения, при расхождении не
   применяем ничего.
2. **Идемпотентность по короткому сентинелу**, а не по всему вставляемому блоку: поправишь опечатку
   в комментарии внутри вставки — и повторный прогон вставит блок второй раз.
3. **Бэкапы отдельным проходом, до первой записи.** Иначе первый файл переписан, а на втором
   бэкап падает: половина правки хуже, чем ни одной.
4. **Запись через временный файл и переименование** — читатель не увидит половины.
5. **Проверка концов строк байтами.** Чтение в текстовом режиме склеит CRLF молча, и запись
   переведёт весь файл на другие концы: диф во весь файл, бесполезный бэкап.
6. **Проверка синтаксиса результата до записи** — для общего модуля, обслуживающего все пулы.

## Ловушки среды

⚠️ **BOM на Windows обязателен.** Локальная копия движка лежит с пометкой кодировки: без неё
PowerShell 5.1 читает исходник как cp1251 и портит всю кириллицу, включая ту, что печатается ролям.
Серверная копия лежит **без** пометки — её исполняет только pwsh 7. Копировать файл с сервера на
рабочую машину нельзя; переносить надо правками.

⚠️ **Копии расходятся.** На момент переноса локальная отставала на 440 строк, причём в обе стороны:
на локальной было своё (печать тела задачи, установка кодировки консоли), чего нет на сервере.
Слияние — выборочный перенос, а не копирование.

⚠️ **Скрипты с регулярными выражениями — только записью файла и заливкой.** Сборка через heredoc
жуёт обратные слэши молча: `\b` приезжает байтом 0x08, и скрипт находит 7 совпадений вместо 910.

⚠️ **`grep -i` не находит кириллицу** под локалью `C.UTF-8`: регистронезависимость там работает
только для ASCII.

## Первый прогон после выката

Порядок, который стоило бы соблюдать всегда:

1. сухой прогон — посмотреть, кому и сколько ушло бы;
2. прогон с засевом — накопленное помечается разобранным, письма не уходят;
3. проверка, что засев лёг во все шины;
4. и только потом — обычная работа.

Проверено: засев лёг во все восемь живых шин, не разослано ничего.
