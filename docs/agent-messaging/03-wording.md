# 03 — Как формулировать: два поля, два разных вопроса

Это самая тонкая часть механики: поля легко заполнить так, что они будут выглядеть правильно
и не значить ничего. Ниже — правила, эталоны и антиобразцы, все с живого прогона.

## Откуда взялось поле «Требуется»

Первая редакция механики его не имела: были имя (ключ) и условие закрытия. Разбор первого
прогона показал провал — **одиннадцать признаков закрытия из одиннадцати описывали форму отчёта**
(«прислан корпус, 136 записей числом, у каждого путь к источнику») и **ни один не говорил, чего
ждут по существу**. Реестр из-за этого читался только вместе с письмами, то есть ровно так же,
как переписка читалась до всякой механики.

## `Expect` — что требуется по существу

Пишется **повелительно**: «Требуется ⟨что должно появиться или быть решено⟩ — ⟨зачем это тебе⟩».

Вторая половина не украшение: она отличает предмет от пересказа темы письма. «Требуется пилот
роли такой-то» — отписка. «Требуется корпус утверждений из памяти оператора — вход для встречной
проверки поведением, без него сверять нечего» — предмет.

## `CloseWhen` — по какому событию ждущий увидит, что дождался

🛑 **Признак обязан читаться ОТДЕЛЬНО от письма.** Через час ждущий встретит его в своде, где
рядом не будет ни темы, ни текста. Поэтому предмет называется своим именем: не «оба документа»,
не «он», а «карта пересечений и разбор памяти».

**Состав признака:**

- ждёшь вещь — назови три: **предмет**, **где он появится**, **по чему видно, что это всё, а не
  часть** (число, полнота, перечень);
- ждёшь решение — назови **предмет** и **перечень допустимых ответов**.

🛑 **Признак описывает предмет, а не приёмку.** «Заказчик ответил „принимаю"» писать нельзя:
приёмка и есть закрытие, вышло бы «закрыто, когда я закрыл».

🛑 **«Сосед ответил» — негодный признак для развилки, уходящей вверх.** Живой случай: ревизор
открыл обязательство с признаком «руководитель ответил: так или эдак». Руководитель ответил —
событие наступило, обязательство закрыто как выполненное. Но ответа по существу она не знала:
вопрос был не в её власти, она передала его выше. По бумагам закрыто, по делу висит. Пиши
в признак **само решение**, а не факт получения ответа.

## Эталоны

**Ждёшь вещь:**

```
-Opens korpus-utverzhdenij
-Expect "Требуется корпус утверждений из памяти оператора — вход для встречной проверки
         поведением, без него сверять нечего"
-CloseWhen "корпус утверждений памяти оператора прислан, в нём названо число прочитанных
            записей из 136, у каждого утверждения указан путь к источнику"
```

**Ждёшь решение:**

```
-Opens sostav-snimka
-Expect "Требуется решение по рабочей зоне оператора, которой нет в снимке — от него зависит,
         проверяемы ли 59 записей памяти из 136"
-CloseWhen "пришёл ответ, в котором названо, что делать с отсутствующей зоной: исключена
            намеренно, дать листинг или доснять в снимок"
```

## Антиобразцы (все встречались на живом прогоне)

| Что написано | Чем плохо |
|---|---|
| «Требуется пилот роли X» | пересказ темы письма, предмета нет |
| «прислан корпус» | не сказано, где, и по чему видно, что это всё |
| «исполнитель объявил, что закончил» | проверять нечего; именно так собрались 19 писем и треть объёма дня |
| «оба документа приняты» | «оба» — местоимение; в своде рядом нет ни темы, ни текста |
| «заказчик ответил „принимаю"» | описывает приёмку, а не предмет |
| «lead ответил: X или Y» | наступит и без решения — см. выше |

## Длина

Диапазона в знаках нет намеренно: любой порог по числу символов ловил бы форму, а не содержание,
и подталкивал бы дописывать воду до минимума. Для ориентира — как выглядят формулировки,
признанные годными на живом прогоне:

| | мин | средн | макс |
|---|---|---|---|
| `Expect` | 141 | 151 | 162 |
| `CloseWhen` | 183 | 250 | 314 |

Для сравнения: в первой редакции, где `Expect` не существовало, признаки были вдвое короче
(55 / 106 / 164) — и именно они описывали форму отчёта вместо предмета.

## Одно письмо — один предмет

Письмо, которое открывает или закрывает обязательство, несёт один предмет. На первом прогоне
в трёх случаях из одиннадцати признак закрытия наступил **в чужом треде** — потому что закрывающее
письмо везло сразу три темы, поле проставлялось с опозданием, а однажды и вовсе не тем участником.

Машина этого не проверит: отличить три темы от одной без чтения смысла нельзя.
