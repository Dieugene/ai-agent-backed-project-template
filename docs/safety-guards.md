# Safety Guards

Механический предохранитель против самой дорогой ошибки автономного агента —
рекурсивного удаления, нацеленного на пустую переменную или корень. Это
**отдельный слой защиты**, который срабатывает даже там, где обычные
подтверждения отключены. Читать, если поднимаешь workspace, где сессии работают
под `--dangerously-skip-permissions`, или настраиваешь хуки Claude Code.

> Плейсхолдеры: `<user-home>` / `$env:USERPROFILE` — домашняя папка; `<VAR>` —
> любая shell-переменная.

---

## 1. Зачем

Классическая катастрофа: агент генерирует рекурсивное удаление вида
«переменная, сразу слэш, звёздочка» (`<VAR>/` + `*`). Пока переменная
осмысленна — команда безобидна. Но если переменная **пустая или неустановлена**
(опечатка в имени, не прогрелся scope, сорвался предыдущий шаг), shell
подставляет пустую строку — и цель схлопывается в корень. Рекурсивное удаление
уезжает по всему дереву. Это случилось дважды как near-miss, прежде чем появился
барьер.

Вывод: **дисциплине модели тут доверять нельзя** — нужен механический барьер в
харнессе, который ловит опасную форму до исполнения, независимо от того, что
«подумала» модель.

---

## 2. Что ловит, что пропускает

Хук — глобальный `PreToolUse`-обработчик. Он читает JSON события из stdin,
достаёт `tool_input.command` и срабатывает, только если команда — **рекурсивное
удаление** (`rm` / `rmdir` / `del` / `Remove-Item` с флагом рекурсии) **и** его
цель попадает в одну из катастрофических категорий:

| Категория цели | Форма (фрагменты, не полные команды) |
|----------------|--------------------------------------|
| Переменная прямо перед слэшем | `$VAR/`, `${VAR}/`, `"$VAR"/`, `$VAR\`, `$env:X/` — тот самый инцидентный паттерн |
| Корень файловой системы | голый `/` или `/*` |
| Домашняя папка | `~`, `~/`, `$HOME`, `$USERPROFILE` |
| Корень диска (Windows) | `C:\`, `C:\*` |

Матч — блокировка: хук возвращает `permissionDecision = deny` с пояснением,
почему и как переписать безопасно.

**Барьер сургичен** — нормальные удаления проходят без помех:

- `rm -rf node_modules`, `rm -rf ./build/dist` — именованный/относительный путь,
  разрешено.
- `rm -rf "${VAR:?unset}/x"` — безопасная форма (переменная защищена, см. §5),
  разрешено.
- `rm -f somefile.txt`, `git rm -r --cached foo`, `ls -la /etc` — не рекурсивное
  удаление опасной цели, разрешено.

Код целиком не дублируем — см.
[`../scripts/block-dangerous-rm.ps1`](../scripts/block-dangerous-rm.ps1).
Скрипт намеренно **ASCII-only**: так он выведен из-под BOM-ловушки PowerShell
(см. [Windows / PowerShell Pitfalls §1](windows-powershell-pitfalls.md)) и его
можно править чем угодно без риска сжечь кодировку.

---

## 3. Работает под `--dangerously-skip-permissions`

Ключевое свойство. `--dangerously-skip-permissions` отключает **обычные**
запросы-подтверждения харнесса — но `PreToolUse`-хук это **другой слой**, и он
продолжает выполняться. Именно поэтому барьер и нужен: пул-агенты и автономные
сессии почти всегда запускаются со skip-permissions (иначе автономность
невозможна), и встроенный гард харнесса под этим флагом уже не спрашивает.
Хук закрывает ровно эту дыру — он не «ещё одно подтверждение», а независимая
проверка, которую флаг не снимает.

## 4. Регистрация и self-test

**Установка.** Скрипт кладут в `<user-home>\.claude\hooks\` и регистрируют
**глобально** в `<user-home>\.claude\settings.json` (не в проектном
`settings.local.json`) — так его подхватывают все сессии на машине: пул-агенты,
Launcher, DevOps.

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash|PowerShell",
        "hooks": [
          {
            "type": "command",
            "command": "powershell -NoProfile -ExecutionPolicy Bypass -File \"<user-home>\\.claude\\hooks\\block-dangerous-rm.ps1\""
          }
        ]
      }
    ]
  }
}
```

Matcher `Bash|PowerShell` — обе оболочки, которыми агент может звать удаление.
Новые сессии подхватывают хук сразу; текущая — после перезагрузки хуков
(`/hooks`) или рестарта.

**Self-test.** У скрипта есть режим `-SelfTest`, прогоняющий набор тест-кейсов
(и опасные-должны-DENY, и безопасные-должны-ALLOW) против матчера:

```
powershell -NoProfile -ExecutionPolicy Bypass -File "<user-home>\.claude\hooks\block-dangerous-rm.ps1" -SelfTest
```

Ожидаемо — все кейсы зелёные. Правишь regex — **обязательно** прогоняй
self-test заново.

Важная деталь дизайна: **тест-кейсы лежат как DATA внутри скрипта**, а не
собираются в командную строку. Поэтому ни одна опасная строка никогда не
попадает в реально исполняемую команду — сама команда запуска self-test'а
чистая.

---

## 5. Дисциплина автора: не эмитить опасные `rm`-строки вообще

Из устройства барьера следует стоячее правило — **для агента, не только для
хука**:

- **Никогда не эмитить литеральную опасную `rm`-строку в исполняемой команде —
  даже как заведомо инертные «тест-данные».** Во-первых, глобальный гард
  среагирует и на неё. Во-вторых, пользователь не обязан верить, что команда
  «на самом деле безопасна». Нужны тестовые опасные строки — держи их **данными
  в файле**, а команда пусть остаётся чистой (ровно как сделано в self-test'е).
  Этот документ по той же причине показывает цели **фрагментами** (`$VAR/`, `/`,
  `~`), а не собирает из них полную катастрофическую команду.

- **Безопасная форма удаления по переменной:**

  ```bash
  rm -rf "${VAR:?not set}/subdir"
  ```

  `"${VAR:?not set}"` заставляет shell **прерваться с ошибкой**, если `VAR`
  пустая или неустановлена, — вместо тихой подстановки пустоты. Плюс всегда
  указывай **конкретный литеральный подпуть** (`/subdir`), а не голый
  `$VAR/*`. Барьер такую форму пропускает именно потому, что она безопасна.
